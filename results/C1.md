# C1: base Qwen3-4B-Thinking-2507 + original prompt

Frozen APPS-test eval split, 500 problems (150 introductory / 300 interview / 50 competition), 4 samples each.
Sampling: temperature 0.6, top-p 0.95, top-k 20, seed 0, `max_tokens` 8192 (reasoning included).
pass@1 is the mean over problems of each problem's fraction of passing samples; the interval is a 95% bootstrap over problems.

We score C1 in two ways.

- **Strict** (`results/c1-3538415`, LS6 job 3538415): a sample that runs out of tokens inside `<think>` has no final answer and scores 0.
- **Budget-forced** (`results/c1-3538415-forced`, Vista job 1140443): requested in the professor's checkpoint feedback. Each sample cut off while reasoning keeps its text. We append Qwen's early-stop sentence ("Considering the limited time by the user, I have to give the solution based on the thinking directly now.") and `</think>`, and the model writes its answer with up to 2048 more tokens, using the same sampling and a fixed seed per sample. That answer is run and scored as usual (`codegen.force_answer`, `tacc/force.sh`). Samples that had already finished reasoning are unchanged. The total budget is therefore 8192 + 2048 tokens.

## The forced samples

- 1,182 of 2,000 samples (59%) stopped while reasoning, and all of them were forced.
- 487 of these (41%) pass every test, and 1,169 produced code that ran.
- 27 used the whole 2,048-token answer budget. The median forced answer that passed was 985 tokens.
- A spot check of passing forced answers found real solutions: interview problem test-0589 (40/40 tests) and competition problem test-3690 (133/133 tests). Several passes are on problems with only 2–3 tests, the weak-coverage risk noted in plan.md.

## Takeaways

- Most of the gap between strict and forced pass@1 comes from the 8k budget, not from wrong solutions. The model has usually worked out the approach by the time it is cut off.
- Only 5 of the 1,182 cut-off samples contained a fenced Python block inside the reasoning. Running "whatever code exists at the cutoff" would barely change the strict score, which is why we force an answer.
- We report both numbers for every condition (C1–C4) and treat the budget-forced score as a separate metric, since it uses more tokens.
- GRPO is trained with the strict reward: a truncated sample scores 0, and problems whose samples all score the same are filtered out. It therefore learns to reason within 8k, and the strict metric is where its effect should show.

## Cost

- Strict generation: 3,957 s on 3× A100 (LS6), plus 36 s of scoring.
- Forcing: 774 s on 1× GH200 (Vista) for 1.26M answer tokens, plus 61 s of scoring. About 0.27 SU for the whole job.
